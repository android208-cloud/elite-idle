# Редактор интерфейса (§132) — как пользоваться и как устроен

Инструмент для нас с пользователем: покрутить вид карточек, строк и кнопок
прямо в игре, посмотреть результат и выгрузить его файлом, чтобы потом
перенести в код. **Не часть игры**: игрок его не видит, в сейв он не пишет.

## Как включить

1. Вкладка «Журнал» → «Для разработчика →» (экран отладки).
2. Кнопка **«Редактор»** — она достаёт в шапку карандаш и убирает его обратно.
   Это отдельное действие: инструмент есть или его нет.
3. **Карандаш** по центру шапки включает сам режим правки. Нажали — карандаш
   закрашен, экран показывает саму вкладку (не отладку), элементы подсвечиваются
   под курсором. Второе нажатие карандаша — выход.
4. «Готово» в панели — тоже выход.

**В режиме правки интерфейс стоит на паузе**: секундный тик не идёт, экран не
перерисовывается, тексты не подменяются. Иначе выделенная строка уезжала бы, а
ползунок дёргался. Пауза именно интерфейсная: время мира считается по часам,
поэтому после выхода всё досчитается сразу — как после свёрнутой вкладки.

Пока правка включена, вкладки внизу работают (по экранам надо ходить) и
отладку они не закрывают. Закрыли отладку «Назад» — правка выключается сама.

## Что можно править

| Нажали на | Что в панели |
|---|---|
| Карточку | высота, радиус скругления, цвет фона |
| Строку текста в карточке | сам текст, размер шрифта, цвет, положение в карточке (слева / по центру / справа) и **сдвиг** по X и Y |
| Кнопку | жёсткая ширина и высота, текст внутри и **сдвиг** по X и Y |

Сдвиг делается через `transform: translate(...)`: элемент уезжает со своего
места, а поток не ломается — соседи остаются на местах, высота карточки не
меняется.

Числа задаются парой «ползунок + поле»: ползунком быстро, полем точно.
Есть «Сбросить» (вернуть элемент как был) и «Скачать JSON» (выгрузить всё).

**В режиме правки настоящие действия игры не работают.** Клик только выбирает
элемент — иначе правка карточки «Топливо» грозила бы покупкой топлива. Исключения
две: сама панель и нижние вкладки (по экранам надо ходить — правки у каждого свои).

## Где живут правки

В `localStorage` под ключом `elite-idle-ui-edits-v1`, отдельно от сейва игры:
это черновик вида, а не прогресс. Внутри — по экранам:

```json
{
  "hangar": {
    "c1":     { "h": 300, "r": 24, "bg": "#204040" },
    "c1.t1":  { "text": "Привет, капитан", "fs": 18, "align": "center", "dx": 12, "dy": -6 },
    "c1.b0":  { "w": 180, "text": "Заправить", "dx": -20 }
  }
}
```

Ключи: `c2` — третья карточка экрана, `c2.t1` — вторая строка в ней, `c2.b0` —
первая кнопка. Экран — `hangar`, `market`, `ship`, `map`, `log`, `pilots`,
`combat`, `salvage`: правки одного не налезают на другой.

## Почему ключи, а не ссылки на элементы

Экран пересобирается через `innerHTML` при каждой перерисовке (а она бывает
раз в секунду). Держать ссылки на узлы бессмысленно: они умирают. Поэтому
`applyUiEdits()` в конце `render()` обходит разметку **одним и тем же
порядком** — карточки в порядке DOM, внутри карточки: строки-листья, затем
кнопки — и накладывает правки по путям. Порядок обхода в разметке и в
применении общий: это единственное, что делает ключи устойчивыми.

Строка текста — **лист** дерева: элемент без дочерних элементов и с непустым
текстом. Кнопки в список строк не попадают (у них свой режим), иначе правки
дрались бы друг с другом.

Атрибуты `data-ui-key` появляются **только в режиме правки**: в обычной игре
разметка остаётся такой, какой её собрали экраны.

## Чего редактор не умеет (сознательно)

* не пишет в сейв игры — правки не переезжают на другое устройство;
* не переживает смену разметки: если экран переделать (добавить карточку
  сверху), ключи съедут, и правки лягут на соседние элементы — их надо будет
  сбросить;
* не правит шапку и полосу вкладок — только то, что внутри `#content`;
* не сохраняет встроенные цвета в `var(--…)`: цвет пишется в hex.

## Проверки

`tools/verify-ui-editor.mjs` — **38 проверок**: кнопка «Редактор» и карандаш
порознь, включение режима, выбор карточки/строки/кнопки, высота, радиус, фон,
текст, шрифт, положение и сдвиги, блокировка настоящего действия, сохранение в
`localStorage`, выживание правок после перерисовки, выход по «Готово», пауза
интерфейса на идущем полёте (отсчёт замирает и оживает после выхода).
